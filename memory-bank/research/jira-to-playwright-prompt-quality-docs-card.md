What are the corresponding Bedrock-specific retirement dates for `anthropic.claude-3-5-sonnet-*` and `anthropic.claude-3-7-sonnet-*`? These must be checked in the Bedrock Model lifecycle console — they are not published in the main deprecation page. (Evidence gap: Bedrock sets independent schedules per their own model lifecycle page.)

2. **Current vQA model ID in production**: The docs confirm Claude 3.5 Sonnet is retired on Anthropic's API. Whether vQA's Bedrock deployment uses a Bedrock-extended lifecycle window is unknown without checking the actual Bedrock model IDs in `ac_parser.py` / environment config.

3. **`ChatBedrockConverse` strict tool-use passthrough**: The langchain-aws docs confirm tool calling is supported but do not explicitly document whether `strict: true` on tool definitions is passed through to the Bedrock Converse `toolSpec.strict` field unchanged. Verification requires checking langchain-aws source or running a test request.

4. **Bedrock structured output + Converse API compatibility with `ChatBedrockConverse`**: The Bedrock docs confirm structured output works with the Converse API. Whether `ChatBedrockConverse` exposes `outputConfig.textFormat` (JSON schema mode) through its LangChain interface needs verification — the langchain-aws integration docs do not enumerate this parameter.

5. **Playwright test-plan schema for vQA**: The spike found no Playwright-native schema for AI-generated test plans. The vQA JSON Compiler defines its own schema. The official Playwright constraint is that output must use Locators API syntax (`getByRole`, etc.) — whether the current schema enforces this or allows raw selectors is an internal codebase question.

6. **LangGraph version pinning**: The LangGraph HITL docs (now at docs.langchain.com) describe `Command(resume=...)` and `stream_events(..., version="v3")`. The vQA LangGraph version and whether it supports these APIs needs confirmation from `requirements.txt` or `pyproject.toml`.
