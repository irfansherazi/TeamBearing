### Open Questions

1. **Bedrock tool-use enforcement level:** Does AWS Bedrock's converse API tool-use enforce JSON schema compliance at the constrained-decoding level (like OpenAI Structured Outputs strict mode) or at the best-effort/function-calling level? The practitioner discourse lane found no Bedrock-specific evidence; the docs lane must resolve this.

2. **Silent failure rate in vQA:** Is there instrumentation in `ac_parser.py` that logs raw parse failures, or does the pipeline silently return partial/empty objects on JSON parse errors? If silent failure is occurring, the actual failure rate in production is unknown.

3. **Negative-path AC coverage:** Do the current Golden 10 benchmark test cases include negative-path and edge-case scenarios, or do they test only happy paths? If LLMs systematically omit negative paths (per HN practitioner reports), the benchmark may not surface this class of failure.

4. **Component name anchoring:** Does the BDD Normalizer output use component names that the JSON Compiler must resolve to action types? If so, what happens when a component name in the BDD step does not exist in the JSON schema's action vocabulary? Is there a fallback or is it hallucinated through?

5. **Batch vs. interactive mode for HITL:** The pre-execution review gate design differs substantially between synchronous and batch pipeline modes. The 27-minute extended thinking runtime and 15-minute reviewer SLA are incompatible with synchronous interactive use. Has the team defined the expected latency envelope for the HITL flow?

### Operational Pitfalls

- **Silent JSON parse failure corruption:** A parse error caught-and-suppressed returns an empty dict that propagates as if valid through the pipeline, corrupting test plans for weeks without surfacing — Tensoria blog, https://tensoria.fr/en/blog/structured-outputs-llm-production (Grade B)
- **Anchoring amplification in chained LLM stages:** A flawed BDD Normalizer output anchors the JSON Compiler, producing confident-but-wrong JSON; fragility impact factors of 6.29-10.31 across multi-agent frameworks — Zylos Research, https://zylos.ai/research/2026-06-29-anchoring-contamination-chained-llm-pipelines/ (Grade B)
- **Hallucinated component names from vague AC:** LLMs hallucinate specific technical requirements (e.g., Redis cache timeout) from vague Jira tickets; without a component registry anchor, fabricated action IDs pass schema validation and execute against wrong targets — multiple practitioner sources, https://true-story.tech/blog/ai-test-case-generation-jira-guide (Grade B)
- **JSON-mode reasoning chain bypass:** Forcing JSON output in a single prompt causes the model to emit the answer field before the reasoning field, bypassing chain-of-thought and degrading semantic quality of the structured output — Google Cloud / Kishore Gopalan, https://medium.com/google-cloud/the-conflict-between-llm-reasoning-and-structured-output-fluid-thinking-vs-rigid-rules-e64fb0509d40 (Grade C)
- **40% test-mirror failure rate even with strong quality processes:** Critical TechWorks industrial study found only 60% of LLM-generated acceptance tests accurately mirrored source Gherkin scenarios under controlled conditions; vQA's noisier AC input will produce worse results — Arxiv 2504.07244, https://arxiv.org/html/2504.07244v1 (Grade B)
- **LLM-as-judge benchmark blind spots:** Using Claude to evaluate Claude's own test plan output maximizes the probability that the judge and the model share the same systematic blind spots; the Golden 10 set may systematically miss a failure class both models agree on — HN item 41019748, https://news.ycombinator.com/item?id=41019748 (Grade C)
- **Hardcoded assertions concealing bugs ("verification gap"):** LLMs optimize for passing tests rather than correct assertions; generated tests pass with mocked values that don't reflect real application behavior — Augment Code blog, https://www.augmentcode.com/guides/why-ai-coding-agents-fail-e2e-tests (Grade B)
- **Extended thinking latency incompatible with synchronous HITL:** Extended thinking adds 10-30x latency at useful quality budgets; a 27-minute runtime per complex call is incompatible with synchronous pre-execution review gate flows — Simon Willison, https://simonwillison.net/2025/Feb/25/llm-anthropic-014/ (Grade C)
- **Prompt-based HITL gates can be bypassed by the agent:** A prompt instruction to "wait for human approval" is not architecturally enforced and can be bypassed through the model's reasoning; only an interrupt node in LangGraph with state persistence constitutes real HITL — Cordum.io, https://cordum.io/blog/human-in-the-loop-ai-patterns (Grade C)
