### Open Questions

1. **voyage-code-2 full specs**: docs.voyageai.com was access-denied in this run. Dimensions, context window, TypeScript support, pricing, and rate limits for voyage-code-2 are unconfirmed from official sources. The PyPI library supports a 1000-input batch limit but model-specific limits are unknown. Requires either manual web access or a session where voyageai.com is reachable.

2. **OpenAI text-embedding-3-small specs**: platform.openai.com was access-denied. Dimensions, max tokens, rate limits, and pricing are unconfirmed. If OpenAI embeddings are a candidate, specs must be verified independently.

3. **Cohere Embed v4 `code` input_type on Bedrock**: The Bedrock-wrapped Cohere Embed v4 may or may not expose `input_type: code`. The official model card only shows `search_document` in sample code. The actual InvokeModel body schema and accepted `input_type` values need verification — this is a blocking question if Cohere Embed via Bedrock is the chosen path for code retrieval.

4. **Bedrock embedding default RPM quotas for this AWS account**: Default RPM values are account-specific and not published in documentation. The vQA team should check the Service Quotas console for `amazon.titan-embed-text-v2:0` and `cohere.embed-v4:0` in their deployed region (us-east-1 or equivalent) before committing to a Bedrock embedding strategy.

5. **ChromaDB default embedding function confirmation**: The ONNX source file confirms `all-MiniLM-L6-v2` with batch_size=32 and max_seq_len=256, but the official docs.trychroma.com embedding-functions page was access-denied. There may be newer default model behavior in ChromaDB 1.5.x that differs from the source file read.

6. **Titan G1 actual retirement status**: The EOL floor date (11/29/2024) has passed. The model card shows "Active" but this may lag actual deprecation signaling. The vQA team should verify via `aws bedrock list-foundation-models` CLI whether `amazon.titan-embed-text-v1` still appears as available in their account region.
