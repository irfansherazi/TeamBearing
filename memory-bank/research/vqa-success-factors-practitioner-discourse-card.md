### TRAP Candidates

1. **Benchmark-to-production navigation gap (78% benchmark → 22% production)**: Agent navigation reliability measured on controlled benchmarks systematically overstates production performance on live SPAs by 40-56 points. Any circuit-breaker threshold derived from benchmark performance data is likely to be miscalibrated for the real Angular/PrimeNG environment. — [FutureAGI Browser-Use Agents 2026](https://futureagi.com/blog/evaluating-browser-use-agents-2026/) (Grade B)

2. **LLM verifier false-positive structural floor (~33%)**: No judge configuration in practitioner evidence exceeds AUROC 0.65 for false-success detection. The ~66% human-expert agreement ceiling means roughly 1 in 3 verifier verdicts is wrong. A PASS from a visual-only LLM verifier without DOM-programmatic grounding is statistically unreliable regardless of prompt quality. — [Getmaxim.ai](https://www.getmaxim.ai/blog/can-llms-actually-judge-web-development-quality-spoiler-not-really/) (Grade B) + [Braintrust](https://www.braintrust.dev/articles/what-is-llm-as-a-judge) (Grade B)

3. **Same-model supervision fallacy**: Using the same LLM model class to verify output it generated does not solve reliability gaps — it shares the same blind spots. HN practitioners explicitly name this as a known-failed pattern. A verifier prompt that catches 90% of LLM executor errors in testing will fail on exactly the class of errors the executor model systematically makes. — [HN 12-factor agents](https://news.ycombinator.com/item?id=43699271) (Grade C) + [Galileo](https://galileo.ai/blog/why-llm-as-a-judge-fails) (Grade B)

4. **LangGraph default recursion_limit is a crash not a circuit breaker**: The default 25-step limit throws a hard Python exception, not a graceful degradation. LangGraph 1.0.6 has a confirmed regression where agents loop through all 25 steps even with explicit stop conditions in the prompt. SubAgentMiddleware silently drops recursion_limit propagation to child graphs, causing CancelledError to bubble unpredictably. Teams that rely on the framework default get 500 errors under load. — [GitHub #6731](https://github.com/langchain-ai/langgraph/issues/6731) (Grade B) + [GitHub deepagents #1698](https://github.com/langchain-ai/deepagents/issues/1698) (Grade B)

5. **Silent session expiry corrupts trajectory rather than failing cleanly**: When a session cookie or OAuth token expires mid-task (Google APIs: 1 hour, Slack: 12 hours), the agent does not detect the auth redirect — it types the next planned action value into the login form field. The resulting trajectory appears as a navigation failure, not a credential failure, making root-cause diagnosis misleading. — [FutureAGI](https://futureagi.com/blog/evaluating-browser-use-agents-2026/) (Grade B) + [Scalekit](https://www.scalekit.com/blog/how-handle-token-refresh-ai-agents) (Grade B)

6. **Passive observability (LangSmith/tracing) does not prevent runaway loops**: Tools like LangSmith produce complete traces of thousands of identical failing tool calls but do not stop execution. An agent ran 8 hours uninterrupted, accruing $437 in costs, with full trace data available throughout. Active enforcement must live inside the graph state, not in the monitoring layer. — [dev.to/waxell](https://dev.to/waxell/ai-agent-circuit-breakers-the-reliability-pattern-production-teams-are-missing-5bpg) (Grade C)

7. **Vague AC causes systematic execution failure above 4 acceptance signals**: Empirical evidence shows a 35-point accuracy drop (95% → 60%) as AC complexity increases from single-signal to 4+ signals. There is no published production-validated quality floor threshold, but the degradation curve is steep enough that ACs with compound conditionals ("AND the user must also see X unless Y") are a near-certain failure class for autonomous execution. — [Arxiv 2604.21505](https://arxiv.org/html/2604.21505v1) (Grade C)

8. **Hard-coded Playwright timeouts create a 68%-floor failure rate independent of LLM quality**: A practitioner case study shows wait-strategy fixes alone moved pass rate from 68% to 98.5%. If vQA uses any `waitForTimeout()` or fixed sleeps for SPA navigation (lazy-loaded PrimeNG tables, Angular route transitions), the LLM quality improvements are masked by an underlying timing failure that will always appear as LLM navigation errors in traces. — [Playwright flaky tests](https://medium.com/@antongulin/how-to-fix-flaky-tests-in-playwright-10-battle-tested-strategies-c1713b90bd79) (Grade C)

9. **Judge calibration drift: prompt that looks reasonable on 3 examples fails in production**: Without a 30-200 example gold set labeled from actual production runs and periodic recalibration, verifier accuracy degrades silently as AC types and UI patterns evolve. A verifier tuned for simple billing-query ACs will systematically miscalibrate when the distribution shifts to complex multi-step navigation ACs. — [Galileo](https://galileo.ai/blog/why-llm-as-a-judge-fails) (Grade B)

10. **Role-credential inheritance means the agent tests as the wrong role**: An agent inheriting an admin user's OAuth session carries admin scope into the entire run. Tests designed for a viewer-role AC execute with admin permissions and may pass where a viewer would fail — producing false passes for role-gated UI elements. — [WorkOS](https://workos.com/blog/developers-guide-to-ai-agent-authentication-and-authorization) (Grade B)
