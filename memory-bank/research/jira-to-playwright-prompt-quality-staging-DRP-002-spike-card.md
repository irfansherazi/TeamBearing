### TRAP Candidates

- **TRAP CANDIDATE — Claude 3.5 Sonnet model gate**: Native Bedrock structured outputs (the strongest, deterministic approach) require Claude 4.5+. vQA currently uses Claude 3.5 Sonnet. Any plan that relies on native Bedrock structured outputs as a drop-in improvement is blocked until the model is upgraded. This is a hard prerequisite, not a configuration change.

- **TRAP CANDIDATE — max_tokens truncation bypasses all guarantees**: Even native constrained decoding on Bedrock does not protect against truncation at `max_tokens`. If the JSON Compiler generates a large test plan, insufficient max_tokens will produce invalid partial JSON regardless of the enforcement mechanism. Must check `stopReason` on every call.

- **TRAP CANDIDATE — LangChain version instability**: `ChatBedrockConverse.with_structured_output()` had a breaking regression in langchain-aws 0.1.17 (KeyError crash). The feature is maintained as a workaround (forced tool-calling), not native implementation, making it vulnerable to silent regressions when langchain-aws updates its internal tool-wrapping logic.

- **TRAP CANDIDATE — Instructor native Bedrock support not yet shipped**: Instructor's PR #2086 for native Bedrock structured outputs was pending-merge as of Feb 2026. Until merged and released, Instructor on Bedrock still uses TOOLS mode (post-generation validation + retry), not constrained decoding. Depending on the release timeline, this may have resolved by July 2026 — verify against current PyPI version.

- **TRAP CANDIDATE — Schema design affects fidelity even with constrained decoding**: Field ordering (reasoning fields before conclusion fields), field name specificity, and description quality have been reported to affect output accuracy by up to 60% independently of which enforcement mechanism is used. Constrained decoding guarantees syntactic compliance but does not guarantee semantic correctness.

- **TRAP CANDIDATE — Guardrails AI / Bedrock Guardrails naming confusion**: The open-source "Guardrails AI" library and AWS "Amazon Bedrock Guardrails" are entirely different products. Neither enforces JSON schema fidelity in the same way as constrained decoding or tool-use forcing. Using either as a substitute for structured output enforcement is a category error.
