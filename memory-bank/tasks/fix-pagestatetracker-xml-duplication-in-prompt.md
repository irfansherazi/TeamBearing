## Task Description

The vQA agent's context window was bloating during execution due to the repeated injection of `<page_state>` XML snippets. 
Investigation of the prompt history logs (e.g. `run-ff0b9a00_iter72_ac19_vision.txt`) revealed that the `dom_snapshot` generated by `PageStateTracker.format_for_prompt()` was being injected into the `error` string of the `ac_step_failure_diary` by `verifier.py` on every `NOT_YET` or rejected verdict. 
Because `planner.py` already includes a master `_page_state_directive` at the top of the prompt, appending the full XML again inside the failure diary for every failed attempt consumed significant context budget and pushed critical constraints out of the LLM's attention window ("lost-in-the-middle").

The fix requires stripping the raw `dom_snapshot` XML from the `verifier.py` critique strings, replacing it with a brief reference: `DOM state: (see <page_state> at top of prompt)`.

## Acceptance Criteria

- AC-HAPPY-1: The `DOM state at rejection:` log in the failure diary no longer contains the raw `<page_state>` XML.

- AC-REGRESS-1: The agent still has access to the `<page_state>` XML via the master directive at the top of the prompt.
- AC-REGRESS-2: The failure diary still correctly tracks other aspects of the failed step (e.g. action type, locator strategy, exact error).
