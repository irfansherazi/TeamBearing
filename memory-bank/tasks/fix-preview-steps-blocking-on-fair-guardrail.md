# fix-preview-steps-blocking-on-fair-guardrail: Fix preview-steps blocking on FAIR guardrail

## Problem
When selecting a Jira ticket in the execution panel, steps generated by the AI were not showing and the start button stayed disabled.

## Root Cause
The FAIR quality guardrail in `ac_parser_node` (`backend/engine/ac_parser.py`) blocks on `await _event.wait()` when the AC quality is "fair" and no pre-parse guidance is provided. This event is designed to be unblocked via a WebSocket `/resume` call from the frontend.

However, the `/preview-steps` endpoint (`routes.py`) uses a stub state with `run_id = "preview-XXXXXX"` — there is no active WebSocket connection for preview runs, so the event is never set. The HTTP request hangs indefinitely.

On the frontend: `previewLoading` stays `true`, `previewSteps` stays `null`, the step preview panel never renders, and the start button stays disabled (because `confirmedSteps` is never set).

## Fix
In `backend/api/routes.py` `preview_steps()`, set `stub_state["pre_parse_guidance_approved"] = True` before calling `ac_parser_node`. This uses the existing bypass mechanism, skipping the blocking wait while still generating steps and surfacing the FAIR quality warning to the UI.
